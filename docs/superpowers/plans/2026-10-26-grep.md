# Grep over a corpus — plan

Issue #107: `codecite grep <corpus> <pattern>` and an MCP `grep` tool that
return cited lines matching an exact string or a regex, for the literal
strings BM25 `search` is weak at (`"jti"`, an error message,
`token_type_hint=\w+`).

## Decisions

- **What is scanned.** A code file's stored text (`document.text`, the text
  `read` cites lines of), line by line, so each line is scanned once and its
  number is the file's own: code chunks can nest (a class and its methods),
  and scanning chunks would report a line once per chunk holding it. A spec
  has no file text, so its `section` chunks are scanned; their line ranges
  don't overlap. A line inside one of the section's steps is cited as the
  step, any other as the section. Only current document versions, as in
  `search`.
- **Order.** Index order: sources in the order they were stored, then their
  documents by path (not by rowid, which a re-index changes), then lines.
  No score. The documents are sorted without their text.
- **Matching.** The `regex` crate, already in `Cargo.lock` through
  `jsonschema`; a new direct dependency of `codecite-core`, no new crate.
  Each line is matched on its own, so `^` and `$` are the line's ends.
  `fixed` escapes the pattern (`regex::escape`), `ignore_case` sets the
  builder's case-insensitive flag. An invalid pattern is a new typed error,
  `BadPattern` (`bad_pattern`), carrying the regex crate's message; an empty
  pattern is `EmptyQuery`, as an empty search is.
- **Filters and limit.** `language`, `path`, `only` and `limit` as `search`
  has them, with the same default (5) and cap (50); scanning stops at the
  limit. The freshness check and `allow_stale` are `search`'s.
- **Shape.** `{"matches": [...]}`, each match `citation`, `kind` (`code`,
  `section` or `step`, as `read` names them), `role`, `license_class`,
  `indexed_at`, `dirty` (code only) and `text`, the line. A line longer than
  500 characters is cut there with `…`, since a minified file can hold a
  1 MiB line. The CLI's `--json` and the tool print the same bytes.
- **Human form.** As `search`'s: a header when every match shares its
  license class and `indexed_at`, then `<n>. <citation>[ · dirty]` and the
  line, trimmed and cut at 120 characters, control characters escaped.

## Steps

1. `codecite-core`: `store/grep.rs` with `GrepQuery`, `GrepMatch`,
   `GrepResults` and `Store::grep`; `Error::BadPattern`. Tests first: fixed,
   regex, case-insensitive, `^` per line, filtered (language, path, only,
   limit), spec section and step citations, current version only, bad
   regex, empty pattern, stale index, long lines.
2. CLI: `codecite grep` with `--fixed`/`-F`, `--ignore-case`/`-i`,
   `--language`, `--path`, `--only`, `--limit`, `--json`, `--allow-stale`.
   Parse tests and an end-to-end test on a real checkout.
3. MCP: the `grep` tool; schema, result-equals-store, bad-pattern error and
   output-schema tests; the stdio test checks CLI and tool bytes agree.
4. Docs: `docs/design.md` (Interfaces, retrieval) and `docs/usage.md`.
5. Time `grep` on the bench corpus (`evals/retrieval/identity-bench.toml`)
   with a script in `experiments/grep-timing/`, and record the numbers.
