# PR Gates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement #5: a GitHub Actions workflow that runs `fmt`, `clippy`, tests and `cargo-deny` on every PR and on pushes to `main`, plus the `deny.toml` it checks against.

**Architecture:** One workflow file, `.github/workflows/ci.yml`, with four parallel jobs named `fmt`, `clippy`, `test` and `deny`. Each installs the compiler from `rust-toolchain.toml` with `rustup`, so CI and laptops use the same toolchain without a second pin. A root `deny.toml` holds the license allow-list, advisory, ban and source policy, and `cargo deny check` gives the same result locally and in CI.

**Tech Stack:** GitHub Actions, rustup 1.29, Rust 1.99.1, cargo-deny 0.20.2, `Swatinem/rust-cache`, `taiki-e/install-action`.

**Spec:** issue #5, `docs/design.md#security` (supply chain) and `docs/design.md#milestones` (M1).

## Global Constraints

- Triggers: `pull_request` on any base branch (no `branches:` filter, because loop PRs stack on each other) and `push` to `main` only.
- Job ids and `name:` values are exactly `fmt`, `clippy`, `test`, `deny`. They become required checks in oss-admin `terraform/codecite`, so renaming one later breaks merges.
- Gate commands: `cargo fmt --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked`, `cargo deny check`.
- Toolchain comes only from `rust-toolchain.toml` (`1.99.1`); the workflow names no Rust version.
- Third-party actions pinned to full commit SHAs, with the tag in a trailing comment:
  - `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1`
  - `Swatinem/rust-cache@6323deb102c322ba6fcbdcafc7e3dddab59af2b6 # v2.9.2`
  - `taiki-e/install-action@8cca0918f8471c33515202b73f56ab27f2bed283 # v2.87.29`
- cargo-deny pinned to `0.20.2`, the version the loop uses locally.
- Workflow `permissions: contents: read`; no secrets used.
- License allow-list: `Apache-2.0`, `MIT`, `BSD-2-Clause`, `BSD-3-Clause`, `ISC`, `Unicode-3.0`. Today's lockfile uses only `Apache-2.0`, `MIT` and `Unicode-3.0` (`unicode-ident`).
- No new Cargo dependencies.

## Review Focus

- A PR whose base is another loop branch (a stacked PR) still runs all four jobs. Pinned by the absent `branches:` filter on `pull_request`; checked in Task 2 Step 3.
- CI uses `1.99.1`, not the runner's preinstalled stable. Each Rust job prints `rustc --version` after `rustup toolchain install`; checked in the `ci` phase against the job log.
- A dependency under a license outside the allow-list fails `deny`. Checked in Task 1 Step 3 by removing `MIT` from a scratch copy of the config.
- A `Cargo.lock` that is out of date with `Cargo.toml` fails `clippy` and `test` instead of being silently rewritten in CI. Pinned by `--locked`; checked in Task 2 Step 4.
- A new push to the same PR cancels the stale run, while pushes to `main` always run to completion. Pinned by the `concurrency` block in Task 2 Step 1.

### Task 1: `deny.toml`

**Files:**
- Create: `deny.toml`

**Interfaces:**
- Consumes: nothing.
- Produces: the policy that `cargo deny check` reads from the repo root, used by the `deny` job from Task 2.

- [ ] **Step 1: Confirm `cargo deny check` fails without a config**

Run: `cargo deny check licenses`
Expected: FAIL. With no config, cargo-deny allows no licenses, so every crate is rejected.

- [ ] **Step 2: Write `deny.toml`**

- `[graph]`: `all-features = true`, so dependencies behind optional features are checked too.
- `[advisories]`: keep the defaults (RustSec database, `unmaintained = "all"`). Add `yanked = "deny"`. Add `ignore = []` with a comment that every entry needs an advisory id and a reason.
- `[licenses]`: `allow` = the list in Global Constraints. Keep the default `confidence-threshold`. Set `unused-allowed-license = "allow"`, because the BSD and ISC entries are there for crates M2 will add.
- `[bans]`: `multiple-versions = "deny"`, `wildcards = "deny"`, `highlight = "all"`. Add `skip = []` with a comment that a duplicate gets a `skip` entry naming the crate, the version, and the upstream reason. That is the "where practical" escape hatch from #5.
- `[sources]`: `unknown-registry = "deny"`, `unknown-git = "deny"`, `allow-registry = ["https://github.com/rust-lang/crates.io-index"]`.

Learn: `cargo deny check` runs four checks. `advisories` matches `Cargo.lock` against RustSec, the database `cargo audit` uses. `licenses` checks each crate's SPDX expression against the allow-list, so `MIT OR Apache-2.0` passes if either side is allowed, while `(MIT OR Apache-2.0) AND Unicode-3.0` needs `Unicode-3.0` as well. `bans` catches duplicate and wildcard versions. `sources` keeps dependencies on crates.io.

- [ ] **Step 3: Run it, including the license failure path**

Run: `cargo deny check`
Expected: `advisories ok, bans ok, licenses ok, sources ok`. Any warning is reviewed: either fix the config or note the reason in a comment.

Adversarial: `sed '/"MIT",/d' deny.toml > /var/tmp/deny-nomit.toml && cargo deny check --config /var/tmp/deny-nomit.toml licenses`
Expected: FAIL, naming `strsim` (MIT only) as rejected.

- [ ] **Step 4: Run the full gate set**

Run: `cargo fmt --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace && cargo deny check`
Expected: all succeed.

- [ ] **Step 5: Commit**

```bash
git add deny.toml
git commit -m "ci: add the cargo-deny policy for licenses, advisories, bans and sources"
```

### Task 2: The CI workflow

**Files:**
- Create: `.github/workflows/ci.yml`
- Modify: `README.md` (the "Build" section)

**Interfaces:**
- Consumes: `rust-toolchain.toml` and `Cargo.lock` from #4, and `deny.toml` from Task 1, which the `deny` job reads.
- Produces: check names `fmt`, `clippy`, `test`, `deny`.

- [ ] **Step 1: Write `.github/workflows/ci.yml`**

- `name: CI`. `on:` has `pull_request:` with no filters and `push: branches: [main]`.
- `permissions: contents: read` at the top level.
- `concurrency: group: ci-${{ github.ref }}`, `cancel-in-progress: ${{ github.event_name == 'pull_request' }}`.
- `env: CARGO_TERM_COLOR: always`.
- Every job: `runs-on: ubuntu-latest`, first step `actions/checkout` (pinned), then a step `rustup toolchain install` that runs with no arguments and then runs `rustc --version`. With no arguments, rustup 1.28+ installs the toolchain and components that `rust-toolchain.toml` names. Older rustup used `rustup show` for this, which no longer installs anything.
- `fmt`: runs `cargo fmt --check`. No cache, because it compiles nothing.
- `clippy`: `Swatinem/rust-cache` (pinned) after the toolchain step, then the clippy command from Global Constraints.
- `test`: `Swatinem/rust-cache` (pinned), then `cargo test --workspace --locked`.
- `deny`: `taiki-e/install-action` (pinned) with `tool: cargo-deny@0.20.2`, then `cargo deny check`. No rust-cache: it builds nothing, and it fetches the RustSec advisory database fresh each run.

Learn: `rust-cache` keys on the job id, the `rustc` version and `Cargo.lock`, so the `clippy` and `test` caches stay separate and a toolchain bump starts a clean cache. `-D warnings` turns every warning into an error, so `missing_docs`, `clippy::all` and the rest of the workspace lints from #4 block merges. The cost: a new compiler can add lints that break a green branch. The `1.99.1` pin keeps that to deliberate toolchain bumps.

- [ ] **Step 2: Lint the workflow**

Run: `actionlint .github/workflows/ci.yml` if `actionlint` is on `PATH`. Otherwise run `python3 -c 'import sys,yaml; yaml.safe_load(open(sys.argv[1]))' .github/workflows/ci.yml`.
Expected: no output and exit 0.

- [ ] **Step 3: Check the triggers and pins by reading the file**

Run: `grep -nE 'uses:|branches|name: (fmt|clippy|test|deny)$' .github/workflows/ci.yml`
Expected: three distinct `uses:` actions, each `@<40-hex> # vX`. `branches` appears only under `push`. All four job names are present.

- [ ] **Step 4: Run the gate commands locally, including the `--locked` failure path**

Run: `cargo fmt --check && cargo clippy --workspace --all-targets --locked -- -D warnings && cargo test --workspace --locked`
Expected: all succeed.

Adversarial: `cp Cargo.lock /var/tmp/Cargo.lock.bak && sed -i '0,/^version = "4.6.7"/s//version = "4.6.6"/' Cargo.lock && cargo test --workspace --locked; cp /var/tmp/Cargo.lock.bak Cargo.lock`
Expected: cargo exits non-zero, saying the lock file needs to be updated (or that the version doesn't match). Then `git diff --exit-code Cargo.lock` is clean.

- [ ] **Step 5: Add the gates to `README.md`**

Under "Build", add one paragraph: CI runs `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` and `cargo deny check` on every PR. Run them locally before pushing; `cargo deny` needs `cargo install cargo-deny --locked`.

- [ ] **Step 6: Commit**

```bash
git add .github/workflows/ci.yml README.md
git commit -m "ci: run fmt, clippy, tests and cargo-deny on every PR"
```
